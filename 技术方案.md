### 1.2 关键第三方依赖

```
依赖关系（SPM Package.swift）:
```

### 1.3 被排除的选项及理由

| 排除选项 | 排除原因 |
|---------|---------|
| Electron | 内存高（250MB+），无原生 Keychain 集成，与 HIG 违背 |

### 2.2 关键设计原则

**原则 A：单向数据流（Unidirectional Data Flow）**

```
用户操作 → Action → Store.reduce() → State 更新 → UI 重渲染
               ↓
          副作用（Side Effects）：网络请求、Keychain 读写、磁盘 IO
```

Store 持有不可变 State 快照，所有突变通过 `send(_ action:)` 方法进入，避免散乱的状态修改。

**原则 B：Actor 隔离并发安全**

所有 Mutable Store 标注 `@MainActor`，SSH 工作线程通过 `async/await` 与主线程通信：

```swift
@MainActor
class SessionStore: ObservableObject {
    @Published var sessions: [Session] = []

    func connect(session: Session) async {
        // Kicks off non-mainthread work
        let conn = await SSHConnectionService.shared.connect(session)
        self.activeConnections[session.id] = conn
    }
}
```

**原则 C：依赖注入（Protocol-based DI）**

核心服务面向协议编程，便于 Mock 和测试：

```swift
protocol SSHConnectionServiceProtocol {
    func connect(_ session: Session) async throws -> SSHConnection
    func disconnect(_ connectionID: UUID) async
}

class SSHConnectionService: SSHConnectionServiceProtocol { ... }
class MockSSHConnectionService: SSHConnectionServiceProtocol { ... }
```

## 3. 模块详细设计

### 3.1 SSH 连接层

#### 3.1.1 架构概览

```
用户触发连接
     │
     ▼
SSHConnectionService.connect(session)
     │
     ├─→ 1. DNS 解析 & TCP 建连（DispatchQueue.global）
     │
     ├─→ 2. SSH 握手（libssh2_session_handshake）
     │
     ├─→ 3. 主机指纹校验
     │       ├─ Known? → 比对缓存指纹
     │       └─ Unknown? → 触发弹窗回调 → 等待用户确认
     │
     ├─→ 4. 认证（按配置顺序尝试）
     │       ├─ Auth/Password: libssh2_userauth_password
     │       ├─ Auth/PublicKey: libssh2_userauth_publickey_fromfile
     │       └─ Auth/Agent: libssh2_agent_userauth
     │
     ├─→ 5. 打开 PTY Channel
     │       libssh2_channel_open_session
     │       libssh2_channel_request_pty
     │       libssh2_channel_shell
     │
     └─→ 6. 返回 SSHConnection 对象，挂入 SwiftTerm
```

#### 3.1.2 SSHConnection 对象设计

```swift
actor SSHConnection {
    let id: UUID
    let sessionConfig: Session
    private var libssh2Session: OpaquePointer?
    private var channel: OpaquePointer?
    private var socket: Int32
    private(set) var state: ConnectionState = .idle

    // 非阻塞轮询：每帧调用，读取服务器数据
    func poll() async -> Data?

    // 写入终端输入
    func write(_ data: Data) async throws

    // 打开 SFTP 子系统（复用现有连接）
    func openSFTPSession() async throws -> SFTPSession

    // 添加端口转发规则（不需要重连）
    func addTunnel(_ rule: TunnelRule) async throws -> TunnelHandle
}
```

#### 3.1.3 nonblocking 模式与事件循环

libssh2 默认阻塞模式会锁死主线程。采用非阻塞模式 + BSD socket + DispatchSource：

```swift
// 设置非阻塞
libssh2_session_set_blocking(session, 0)

// 使用 DispatchSource 监听 socket 可读事件
let source = DispatchSource.makeReadSource(fileDescriptor: socketFD,
                                           queue: sshQueue)
source.setEventHandler {
    self.readAvailableData()
}
source.resume()
```

#### 3.1.4 跳板机（Jump Host）实现

多跳通过 libssh2 的 `direct-tcpip` channel 实现：

```
本机 → [SSH Channel 1 to Bastion] → [direct-tcpip to Target:22] → Target
```

```swift
// 跳板机实现伪代码
func connectViaJumpHosts(_ hops: [JumpHost], target: Session) async throws {
    var currentConn = try await connectDirect(hops[0])
    for hop in hops.dropFirst() {
        let forwardChannel = try await currentConn.openDirectTCPIP(
            host: hop.host, port: hop.port
        )
        currentConn = try await SSHConnection(overChannel: forwardChannel,
                                               credentials: hop.credentials)
    }
    // 最终连接目标
    let finalChannel = try await currentConn.openDirectTCPIP(
        host: target.host, port: target.port
    )
    return try await SSHConnection(overChannel: finalChannel,
                                   credentials: target.credentials)
}
```

#### 3.1.5 自动重连状态机

```
Idle ──connect()──→ Connecting ──success──→ Connected
                         │                       │
                      failure                 网络中断
                         │                       │
                    ConnectFailed          Reconnecting ──超过3次──→ Disconnected
                                                 │
                                              成功
                                                 │
                                           Connected（恢复 PTY 尺寸）
```

重连策略：指数退避，基准 2s，最大 30s，最多重试 3 次。

### 3.2 终端渲染层

#### 3.2.1 SwiftTerm 集成

SwiftTerm 提供 `LocalProcessTerminalView`（本地进程）和 `TerminalView`（数据流驱动）两种模式。ShellMate 使用数据流模式：

```swift
class ShellMateTerminalView: TerminalView, TerminalViewDelegate {

    var connection: SSHConnection?

    override func viewDidLoad() {
        terminalDelegate = self
        // 读取 SSH 数据投喂给终端
        Task {
            while let data = await connection?.poll() {
                self.feed(byteArray: [UInt8](data))
            }
        }
    }

    // 用户键盘输入 → SSH 写入
    func send(source: TerminalView, data: ArraySlice<UInt8>) {
        Task {
            try? await connection?.write(Data(data))
        }
    }

    // 终端窗口尺寸变化 → 通知服务器
    func sizeChanged(source: TerminalView, newCols: Int, newRows: Int) {
        Task {
            try? await connection?.resizePTY(cols: newCols, rows: newRows)
        }
    }
}
```

#### 3.2.2 关键词高亮实现

高亮规则在终端渲染管线后处理，不修改 SwiftTerm 核心：

```swift
// 自定义 HighlightEngine，挂接 SwiftTerm 的 AttributedString 输出钩子
class HighlightEngine {
    var rules: [HighlightRule] = []
    // 预编译正则，避免每帧重新编译
    private var compiledRules: [(NSRegularExpression, HighlightRule)] = []

    func apply(to attributedString: inout NSMutableAttributedString) {
        for (regex, rule) in compiledRules {
            let range = NSRange(attributedString.string.startIndex...,
                                in: attributedString.string)
            for match in regex.matches(in: attributedString.string, range: range) {
                apply(rule: rule, to: &attributedString, range: match.range)
            }
        }
    }
}
```

#### 3.4.2 传输队列

```swift
@MainActor
class TransferQueue: ObservableObject {
    @Published var tasks: [TransferTask] = []

    private let concurrencyLimit = 3  // 最多 3 个并发
    private var activeTasks: [UUID: Task<Void, Error>] = [:]

    func enqueue(_ task: TransferTask) {
        tasks.append(task)
        drainQueue()
    }

    private func drainQueue() {
        let available = concurrencyLimit - activeTasks.count
        let pending = tasks.filter { $0.state == .pending }.prefix(available)
        for task in pending {
            start(task)
        }
    }
}
```

#### 3.4.3 断点续传实现

```swift
func resumeUpload(localURL: URL, remotePath: String,
                  resumeOffset: UInt64) async throws {
    // 1. 打开远端文件（LIBSSH2_FXF_WRITE | LIBSSH2_FXF_APPEND）
    let remoteHandle = libssh2_sftp_open(sftpHandle, remotePath,
                                         LIBSSH2_FXF_WRITE | LIBSSH2_FXF_APPEND,
                                         LIBSSH2_SFTP_S_IRUSR | LIBSSH2_SFTP_S_IWUSR)
    // 2. SFTP seek 到已上传偏移量
    libssh2_sftp_seek64(remoteHandle, resumeOffset)
    // 3. 从本地文件对应偏移量读取继续写入
}
```

### 3.5 端口转发与隧道

#### 3.5.1 本地端口转发（-L）

```
实现方案: 在本地监听 TCP Server Socket，
接受连接后通过 libssh2 开一个 direct-tcpip channel，
将流量桥接到远端目标。

本地 App [ListenerSocket:8080]
    → accept() 新连接
    → libssh2_channel_direct_tcpip(session, "db.internal", 3306)
    → 双向数据复制（读写循环）
```

```swift
class LocalForwardTunnel: TunnelHandle {
    private var listenerSocket: Int32
    private var bridgeTasks: [UUID: Task<Void, Never>] = [:]

    func start() throws {
        // bind + listen 本地端口
        // DispatchQueue 上异步 accept loop
        sshQueue.async { self.acceptLoop() }
    }

    private func acceptLoop() {
        while isRunning {
            let clientFD = accept(listenerSocket, nil, nil)
            guard clientFD >= 0 else { continue }
            Task { await self.bridge(clientFD: clientFD) }
        }
    }
}
```

**Keychain 访问控制设置：**

| 凭据类型 | `kSecAttrAccessible` | 说明 |
|---------|---------------------|------|
| SSH 密码 | `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` | 锁屏后无法访问，不迁移到新设备 |
| 私钥 Passphrase | `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` | 同上 |
| 主密码 verify hash | `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` | 允许后台唤起时验证 |

#### 3.7.2 主密码实现

主密码不以明文存储，采用 PBKDF2 派生加密密钥后对敏感字段加密：

```swift
struct MasterPasswordService {
    // 验证主密码（与存储的 PBKDF2 摘要对比）
    func verify(masterPassword: String) -> Bool

    // 解锁：派生 AES-GCM 密钥，存入内存（不持久化）
    func unlock(masterPassword: String) throws

    // 加密敏感字段（如 notes）
    func encrypt(_ data: Data) throws -> Data  // AES-GCM

    // 解密
    func decrypt(_ data: Data) throws -> Data
}
```

#### 3.7.3 已知主机（Known Hosts）管理

```swift
class KnownHostsManager {
    // 存储路径: ~/Library/Application Support/ShellMate/known_hosts
    // 格式: 兼容 OpenSSH known_hosts 格式

    func check(host: String, port: Int, fingerprint: String) -> KnownHostResult
    func add(host: String, port: Int, fingerprint: String, keyType: String)
    func remove(host: String, port: Int)
    func all() -> [KnownHostEntry]

enum KnownHostResult {
    case unknown       // 首次连接，触发 D02 弹窗
```

## 6. 关键技术难点与解决方案

### 6.1 libssh2 非阻塞模式的 Swift 集成

**难点：** libssh2 是 C 库，非阻塞模式需要手动管理 `EAGAIN` 错误并重试；Swift 的 async/await 与 C 的 callback 模式不兼容。

**解决方案：**
```swift
// 使用 withCheckedThrowingContinuation 将 libssh2 回调桥接为 async
func readChannel() async throws -> Data {
    try await withCheckedThrowingContinuation { continuation in
        sshQueue.async {
            var buffer = [UInt8](repeating: 0, count: 65536)
            let rc = libssh2_channel_read(self.channel, &buffer, buffer.count)
            if rc == LIBSSH2_ERROR_EAGAIN {
                // 注册 DispatchSource，下次可读时重试
                self.scheduleRead(continuation: continuation)
            } else if rc > 0 {
                continuation.resume(returning: Data(buffer.prefix(rc)))
            } else {
                continuation.resume(throwing: SSHError.channelClosed)
            }
        }
    }
}
```

### 6.2 App Store Sandbox 下的 SSH Agent 访问

**难点：** SSH Agent 通过 UNIX Domain Socket（`$SSH_AUTH_SOCK`）通信，Sandbox 限制跨进程 socket 访问。

**解决方案（双版本策略）：**

| 版本 | 处理方式 |
|------|---------|
| App Store 版 | 不支持 SSH Agent（在 UI 中明确说明），提示用户改用私钥文件认证 |
| Direct 版（官网下载） | 无 Sandbox，正常访问 `SSH_AUTH_SOCK` |

代码判断：
```swift
#if SANDBOXED
    // 禁用 Agent 选项，显示说明文字
#else
    let agentSocketPath = ProcessInfo.processInfo.environment["SSH_AUTH_SOCK"]
#endif
```

### 6.3 SwiftTerm 与 libssh2 的数据竞争

**难点：** SwiftTerm 要求在主线程 feed 数据，libssh2 poll 在 sshQueue；高频输出（如 `cat large_file`）可能造成主线程积压。

**解决方案：** 引入背压（Backpressure）机制：

```swift
// 使用 AsyncStream 作为缓冲队列
let (stream, continuation) = AsyncStream<Data>.makeStream(
    bufferingPolicy: .bufferingNewest(100)  // 最多缓存 100 个数据块
)

// sshQueue 侧：生产数据
continuation.yield(data)

// MainActor 侧：消费数据（60fps 帧率驱动）
Task { @MainActor in
    for await data in stream {
        terminalView.feed(byteArray: [UInt8](data))
    }
}
```

### 6.4 Core Data + CloudKit 同步冲突

**难点：** 多设备同时修改同一 Session 配置，CloudKit 可能产生合并冲突。

**解决方案：**
- 使用 `NSMergeByPropertyObjectTrumpMergePolicy`（最新写入版本优先）
- 为关键字段添加 `modifiedAt: Date` 属性，自定义冲突仲裁逻辑
- Session 删除操作采用软删除（`isDeleted: Bool`），同步到所有设备后再彻底清除

### 6.5 终端 Unicode/CJK 字符正确渲染

**难点：** CJK 全角字符宽度是半角的 2 倍，与等宽字体的列计算不匹配，导致光标错位。

**解决方案：** SwiftTerm 已内置 Unicode 宽度表（基于 Unicode UCD），配合设置「非 ASCII 字体」（如冬青黑体）：
```swift
terminalView.font = NSFont(name: "JetBrainsMono-Regular", size: 13)!
terminalView.nativeFont = NSFont(name: "HiraginoSansGB-W3", size: 13)!
```

## 7. 性能设计

### 7.1 冷启动优化

**目标：** < 2 秒（PRD §5.1）

| 优化手段 | 说明 |
|---------|------|
| 懒加载 SessionStore | 首屏仅加载分组结构，会话详情按需加载 |
| Core Data Batch Fetch | 使用 `NSBatchFetchRequest` 减少行数，首屏最多加载 100 个会话 |
| 异步预热 | 启动时不建立任何 SSH 连接，等用户主动触发 |
| `@MainActor.run` 批量更新 | 合并多次 `@Published` 变更为一次 UI 更新 |

### 7.2 终端渲染性能

**目标：** ≥ 60fps，键盘延迟 < 16ms（PRD §5.1）

| 优化手段 | 说明 |
|---------|------|
| Metal 渲染后端 | SwiftTerm 支持 Metal 加速文字渲染，启用 `preferredFramesPerSecond: 120` |
| 滚动缓冲区分页 | 回滚缓冲区最多 10,000 行，使用虚拟列表渲染（仅渲染可见区域） |
| 高亮规则预编译 | 应用启动时预编译所有正则 `NSRegularExpression`，避免每帧重新解析 |
| 数据分块 feed | 单次 feed 最大 64KB，过大数据分块避免主线程卡顿 |

### 7.3 搜索性能

**目标：** 500 会话搜索 < 100ms（PRD §5.1）

```swift
// 内存中全量 sessions 数组，使用 Trie 实现模糊匹配
// 对于 500 个会话，线性扫描也远低于 100ms 阈值
// 搜索在 DispatchQueue.global(qos: .userInteractive) 执行
// 结果通过 MainActor 更新 filteredSessions

func search(_ query: String) {
    Task.detached(priority: .userInitiated) {
        let results = self.allSessions.filter {
            $0.name.fuzzyMatch(query) ||
            $0.host.contains(query) ||
            $0.username.contains(query)
        }
        await MainActor.run { self.filteredSessions = results }
    }
}
```

### 8.1 密钥存储安全边界

### 8.2 网络安全

- SSH 通信全程 libssh2 加密，禁用弱算法（见 PRD §3.10.4）
- 在 `SSHConnectionService` 中显式配置算法偏好列表：

| SwiftUI 动画在 macOS 13 低版本卡顿 | 中 | 低 | 使用 `withAnimation` 而非 `.animation` 修饰符；测试 macOS 13 最低版本 |

## 附录 B：关键术语

| 术语 | 说明 |
|------|------|
| PTY | Pseudo Terminal，伪终端；数据通过 `libssh2_channel_request_pty` 申请 |
| EAGAIN | libssh2 非阻塞模式返回值，表示需要等待 socket 可读后重试 |
| Actor isolation | Swift 并发模型，`actor` 类型保证内部状态串行访问 |
| Backpressure | 生产者速率超过消费者时的背压机制，防止内存无限增长 |
| Repository pattern | 数据访问抽象层，隔离 Core Data 的具体实现 |
| XCFramework | Apple 多架构 framework 格式，同时包含 arm64 + x86_64 |
