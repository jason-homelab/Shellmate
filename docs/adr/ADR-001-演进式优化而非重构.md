# ADR-001：演进式优化而非重构

**状态**：已采纳
**日期**：2026-06-07
**决策者**：Tech Lead

## 背景

UE Review 列出 27 个用户体验问题。是否应当借机做架构大重构？

## 决策

**不做大重构。** 现有 Core / Features / Shared 三层 + Service-Repository-Store 模式是健康的。通过 **补 5 个横切层 + 1 次有针对性的拆分** 解决问题。

## 理由

1. 27 个问题归并为 5 个根因，均可通过横切关注点抽象解决，不需要触动核心架构
2. 大重构会阻塞 6 周内业务交付
3. 现有 DesignTokens 体系、Feature 隔离已达到可演进的基线水位
4. 增量风险可控；大重构风险一次性爆发

## 后果

- ✅ 6 周内可见交付
- ✅ 业务功能开发不中断
- ⚠️ TerminalView 1200 行的拆分作为唯一例外（已隔离在 W5）
